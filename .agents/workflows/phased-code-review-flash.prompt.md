# ハイブリッド・コードレビュー・プロセス (Flash Indexing Phase)

本レビューは、広大なコンテキストウインドウにおけるLLMの「迷子現象 (Lost in the Middle)」を防ぎ、モデルの特性を最大化するために、【Flash (高速インデキシング)】 と 【Pro (精密推論)】 の2セッションに分けたハイブリッド体制で実行します。

## 0. セッションIDの自動割り出し (Session Indexing)

本タスクを開始する前に、必ず以下の手順で今回の共通セッションID `{SSS}` を自動的に特定・決定してください。

### セッションID `{SSS}` の割り出し規則:

- `./tmp/code-reviews/` ディレクトリ内の既存ファイルを確認します。
- ファイル名先頭の数値（例: `001-phase01-...` の `001`）の中で最大のものを特定し、それに 1 を加算した 3 桁のゼロパディング数値（例: 最大が `001` であれば `002`）を、今回の共通セッションID `{SSS}` とします。
- 既存ファイルがなければ `{SSS}` は `001` とします。

## 0.5. メタスキャン要否の簡易判定 (Meta-Scan Necessity Check)

本タスクのメタスキャン（インデックス作成）を実行する前に、プロジェクトルートで以下のコマンドを実行し、メタスキャンの要否を判定してください。
※もし今回のレビュー対象ディレクトリ（またはファイル）が指定されている場合は、引数としてそのパスを渡してください（例: `node bin/check-meta-scan.js src/Tilly.CoreApp`）。指定がない場合は引数なしで実行してください。

```bash
node bin/check-meta-scan.js [対象パス]
```

出力結果を確認し、以下のように処理を分岐してください：
- **`STATUS: NOT_RECOMMENDED` と出力された場合**:
  出力された推奨および問いかけメッセージをそのままユーザーに提示した上で、タスクを終了してユーザーの入力を待ってください。他に追加の対話やツール実行は行わないでください。
- **`STATUS: RECOMMENDED` または `STATUS: SKIP` と出力された場合**:
  判定内容（推奨理由）をユーザーに簡潔に報告し、そのまま `STEP 1` に進んでください。

## STEP 1: 【Flashモデル向け】メタスキャンセッション

### 1. 実行指示

対象ソースコード全体の変更差分（またはファイル全体）をインプットとし、`skills/code-meta-scanner/SKILL.md` の基準に基づいて「メタインデックス（JSON）」を生成してください。

### 2. 出力・保存要求

「0. セッションIDの自動割り出し」で決定した共通セッションID `{SSS}` を用いて、生成した JSON データを `./tmp/code-reviews/{SSS}-meta-index-active.json` に書き込んで保存してください。
保存が完了したら、一切の説明や挨拶を省き、純粋な JSON データのみを出力してください。

### 3. セッションの終了（ハンドオフ）

JSON データの出力と保存が完了したら、必ず以下のメッセージをユーザーに出力した上で、タスクを終了してユーザーの入力を待ってください。他に追加の対話は行わないでください。

> メタスキャンが完了し、`tmp/code-reviews/{SSS}-meta-index-active.json` に保存しました。
> Proモデルに切り替えて、このタスクを再開してください。準備ができたら「はい」または「y」と入力してください。
